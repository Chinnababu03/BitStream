Executive Summary

This review identifies 4 deepening opportunities that would transform shallow modules into deep, testable, and AI-navigable modules. The current architecture suffers from god objects, tight coupling, and zero testability. Each candidate below addresses a specific friction point with concrete before/after visualizations.

1. Extract Configuration Module

Files: web/app.py, main.py

Strong

Problem

Configuration is scattered across multiple files with hardcoded defaults. The Windows-only path C:\Users\chinn\Downloads\... breaks on other systems. No validation, no environment variable precedence, no testing.

Solution

Create a config.py module with a Settings dataclass. Use environment variables with sensible cross-platform defaults. Add validation and make it injectable for testing.

Benefits

  • • Localité: All configuration in one place — no hunting across files
  • • Leverage: Tests can inject different configs without touching env vars
  • • Testability: Configuration becomes a seam for mocking

2. Extract Event Bus

Files: core/torrent_client.py, core/youtube_client.py

Strong

Problem

Both clients duplicate the same callback pattern: callbacks: List[Callable], add_callback(), _notify(). The web layer tightly couples to client internals by registering callbacks at module level.

Solution

Create an EventBus class with typed events. Clients emit events; the web layer subscribes. Decouples producers from consumers entirely.

Benefits

  • • Localité: All event routing in one place
  • • Leverage: Can add logging, replay, or filtering in one spot
  • • Testability: Subscribe mock handlers in tests

3. Unify Download Manager Interface

Files: core/torrent_client.py, core/youtube_client.py, web/app.py

Worth Exploring

Problem

The web layer handles torrents and YouTube downloads completely separately with duplicate code paths. Adding a new download type (e.g., Usenet, direct HTTP) requires modifying multiple route handlers.

Solution

Create a DownloadManager facade that wraps both clients behind a unified interface. The web layer calls one API instead of two.

Benefits

  • • Localité: All download logic behind one interface
  • • Leverage: New download types only need to implement the interface
  • • Testability: Mock the entire download subsystem in one go

4. Add Dependency Injection Container

Files: web/app.py, main.py

Worth Exploring

Problem

Clients are instantiated at module import time in web/app.py. This makes testing impossible without monkey-patching. The sys.path.insert hacks are fragile.

Solution

Use a simple factory pattern or Flask's app.app_context() to create and inject clients. Proper Python package imports replace sys.path hacks.

Benefits

  • • Localité: All wiring in one place
  • • Leverage: Swap implementations for testing or different environments
  • • Testability: Inject mocks without monkey-patching

🏆 Top Recommendation

Start with Candidate #1: Extract Configuration Module

This is the highest-leverage, lowest-risk change. It:

  • ✓ Fixes the Windows-only default path bug immediately
  • ✓ Creates a clean seam for testing all other components
  • ✓ Takes ~30 minutes to implement
  • ✓ No behavioral changes — pure structural improvement
